# 0001 接管宿主权限控件座位

- 状态：生效
- 日期：2026-10-10（首版）

## 背景

用户要求 composer 里**只保留一个**权限控件，且新增的两档必须带自己的符号与颜色。
宿主自带的控件硬编码只有三档图标（`read-only` / `workspace-write` / `danger-full-access`），
新增档位在它下面显示为无图标，且顺序也无法插入。

## 决策

在 `conversation.input.permission` 注册自己的控件，`priority: -1` 覆盖宿主控件。

## 后果

- 座位是 `kind: 'single'`：同一优先级重复注册会抛错，且抛错发生在 inject 的延迟路径里，表现为“静默无效”。
  `check-seat.mjs` 复刻了这条规则，删掉 `priority` 会红。
- 宿主升级若改动该座位的签名或控件 props，本插件需要同步；这是接管式扩展的固有代价。
- 好处是五档的名字、颜色、图标、字体全部由插件掌握，与宿主三档的几何保持一致。

## 替代方案

1. **新增一个控件**：被用户明确否决（输入框里会出现两个权限按钮）。
2. **改宿主源码**：越界，且升级即丢。
3. **只加预设不加控件**：新增两档无图标、无法着色，体验割裂。
