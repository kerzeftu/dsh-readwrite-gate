# 0003 授权是对话内内存态

- 状态：生效
- 日期：2026-11-15（review 后定案）

## 背景

最初的设计希望通过“回放会话日志里的授权问答”让授权跨重启存活。
实际实现里授权页走的是 `userQuestions.ask()` 服务，不是 `ask_user_question` 工具，
答案不会写成 `tool/call` 记录，日志回放对本插件是空转——于是“撤销后授权又回来”“重启后授权还在”两种行为都不可靠。

## 决策

授权只存在 Harness 进程内存里，按会话隔离：

- `session/disposed` 清空；`agent/disposed` 不清（agent 重建比会话频繁）。
- 派发子会话从父会话的**实时缓存**继承，而不是回放父会话日志。
- 重启 Harness 后全部失效，下次越界重新询问。

## 后果

- 行为可预测：撤销就是撤销，重启就是重问。
- “该对话中总是允许”在长对话里仍然有效（不掉），符合用户预期。
- 代价：进程重启后用户要重新点一遍；这是可接受的，且比“授权悄悄复活”安全。

## 替代方案

写一份旁路持久化（文件/数据库）：能跨重启，但要处理会话标识、失效、清理、并发，收益不抵复杂度。
若将来确实需要，应作为显式配置项引入，而不是默认行为。
