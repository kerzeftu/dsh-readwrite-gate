# 计数刷新与跨平台兼容性构建计划

日期：2026-11-15  
基线：`d29edd9`（1.3.0）  
状态：待确认实施。本轮仅编写文档，没有修改运行代码、安装状态或发布标签。

先阅读[诊断文档](diagnosis-refresh-and-portability.md)。本文规定构建顺序、测试与阶段出口，不把候选 API 或尚未验证的平台当成既定能力。

## 一、交付目标

1. 用户在审批页授予目录后，不打开“额外可读写文件”面板也能看到正确计数；拒绝、仅一次不能增加持续授权计数。
2. Windows 原生终端、Windows 桌面版、macOS 原生终端、Linux 原生终端及 WSL2 使用一致的权限规则，不依赖作者的目录和挂载配置。
3. 保留五档语义、读写分离、写授权隐含读、目录覆盖子树、按对话隔离、撤销规则及无回答通道时失败关闭。
4. 分平台提供证据。不能将“能安装”“Node 测试通过”写成“权限行为已完整验证”。

本轮不新增权限档位，不重写全部插件，不重构无关界面，不实现新的 TUI，不改变授权内存态的既有约定，不直接推翻或覆盖已发布的 `v1.3.0`。

## 二、阶段顺序

| 阶段 | 内容 | 前置条件 | 交付物 |
|---|---|---|---|
| 零 | 固定契约与建立失败回归 | 确认实施 | API/环境矩阵、可重复的失败测试 |
| 一 | 修复列表同步 | 阶段零确认同步契约 | 计数修复、异步生命周期测试 |
| 二 | 统一宿主路径语义 | 阶段零确认各平台路径与沙箱边界 | 路径适配、文件系统安全回归 |
| 三 | 命令解释器与目录选择适配 | 阶段二 | PowerShell/POSIX 分流、能力驱动的目录浏览 |

## 阶段零：固定契约与建立失败回归

### 工作内容

- 记录当前源码提交、实际安装包提交、DSH 版本、宿主 OS、解释器、界面载体。先确认正在测试的是哪个 profile 的副本，不能只修改源码仓库后观察旧安装。
- 对 `0.2.1-alpha.1`、`0.2.2-rc.3` 分别检查问答请求、客户端投影、目录选择器、远程连接及插件卸载契约。遇到未公开能力，先用 Inspect 和该版本文档核实，不能猜事件名。
- 确认 `/access-allow list` 是否写入会话日志、是否触发其他持久副作用，以及多会话调用成本；这决定能否把命令读取用于周期同步。
- 找出是否存在稳定的授权提交后通知或可用的只读订阅机制。问答 waterfall 不作为被动事件总线使用。
- 记录原生 Windows 桌面版的确切 DSH 版本与插件安装方式。没有环境时先保留“未验证”，不阻止写单元测试，但阻止宣布该平台验收完成。

### 先建立会失败的回归

- 模拟服务直调的授权完成，不增加 `userQuestions.settled`；宿主列表已有新目录，控件未打开。现版本应不能自行更新。
- 延迟宿主写入，避免测试把“提交答案”和“授权已保存”当同一时刻。
- 模拟两个会话、两个控件实例、卸载、旧请求晚到、拒绝、仅一次、断线和后台状态。
- 记录 Windows 文件 URL、UNC 共享边界、反斜杠路径父目录解析、POSIX 反斜杠名称等当前失败样例。纯解析用例不访问实际敏感文件。

### 阶段出口

新增测试必须能在基线上暴露问题；记录预期失败与实际输出。原有测试基线也要运行一次。测试脚本不能靠绝对机器路径或硬编码 hook 槽位制造假通过。

## 阶段一：修复列表同步

### 选型原则

按以下顺序选择，不预先承诺只改客户端：

1. **提交后通知**：若两版 DSH 提供稳定契约，宿主完成授权/撤销后按 session 发通知，客户端收到后重读权威列表。通知只表示失效，不把前端缓存当授权依据；重连和首次挂载仍须取快照。
2. **可见页面周期同步**：若没有稳定通知，且阶段零证明现有列表读取无持久副作用，则先使用该只读路径定期校准。否则增加经契约验证的专用只读接口，再同步。不能因为实现方便持续写命令日志。

不截获 `user-questions/request` 的应答链，不伪造工具事件，不修改审批结果，不依赖 bundle 加载次序。

### 周期同步方案的具体约束

- 同一客户端、同一会话共享一个同步器，多个控件不能各开一个定时器。前端只读取，授权仍由宿主决定。
- 正常周期默认 3 秒；单次读取未完成时不再发请求。请求中的布尔状态或 promise 与序号分开维护，`refreshTicket` 不能代替并发锁。
- 开面板、窗口获得焦点、页面重新可见和连接恢复时可请求立即校准，但需合并突发触发。`visibilitychange` 挂在 document，`focus` 挂在 window。
- 页面隐藏时取消周期调度，回到前台立即取快照；没有 DOM/未挂载客户端时不创建计数同步器。
- effect 清理、会话切换、插件卸载使旧请求失效，旧结果不得更新新实例，更不能在迟到后 `setEntries(null)` 清掉新数据。
- 断线时退避重试，不无限并发、不清空已知有效列表。失败状态应能区分“尚未同步”与“已确认没有授权”。
- 改成完成后调度下一次读取，避免请求变慢时积压。恢复后的延迟由前台调度及宿主往返决定，不承诺被挂起页面的实时更新。

### 验收指标

- 页面可见、连接健康、单次读取不超过 1 秒时，宿主完成目录授权后 5 秒内更新计数，无需点击面板；采用推送时目标为通知到达后 1 秒内开始校准。
- 同一会话、同一客户端的空闲周期请求不超过每分钟 20 次；隐藏期间为零。多控件挂载不增加周期数。显式用户增删路径产生的读取另计。
- 一个会话新增/撤销不会改另一个会话；“不允许”和“仅一次”不新增持续授权条目。计数与面板使用同一列表去重结果，不在浏览器猜测授权已成功。
- 焦点始终留在同一个窗口、没有任何 `focus` 事件时，也能通过周期同步更新。

### 测试与阶段出口

新增行为级假定时器测试：模拟真实响应时序、可见性、慢请求和卸载。移除周期触发、故意让旧请求覆盖、取消会话过滤分别应让测试变红。源码文本断言只作补充。

跑完整测试，并在当前 Web UI 实测批准、拒绝、仅一次、撤销及后台恢复。不允许为通过测试删掉原有“已批准条目不得越过更窄档位”等权限回归。

主要影响：`client.js`、客户端测试；只有阶段零确认需要只读通知/接口时才改 `index.js`，并明确安装与重启要求。

## 阶段二：统一宿主路径语义

### 工作内容

建立统一的路径处理边界，手动输入、工具参数、授权存储与包含判断共用明确规则；是否拆出独立模块由实际实现决定，不为模块化而扩展重构范围。

1. 按宿主系统解释路径，不按浏览器系统推断。优先使用 Node 的原生路径/URL 能力及明确的 `path.win32`、`path.posix` 适配，避免多套手写 URL 解码不一致。
2. 区分盘符绝对路径、盘符相对路径、根相对路径、UNC、扩展长度前缀和设备命名空间。不能确认上下文的形式拒绝或要求用户输入绝对路径，不能误判为工作区内。
3. UNC 的 server/share 是不可被 `..` 弹出的根；不同盘符和共享之间不能继承授权。Windows 大小写归一保留既有能力，同时验证大小写敏感目录，不能一律转小写扩大授权。
4. 处理文件 URL 的盘符、localhost、UNC、空格、中文与百分号，保证手动输入和命令分析入口结果一致；禁止把 URL 主机名丢掉后当本地相对目录。
5. 解析已存在祖先的软链/联接，再追加不存在叶子。对权限错误、网络错误、循环链接与真正的不存在作区分，不能遇错回退成“安全路径”。
6. 限制 canonical 缓存有效期或作用域，测试链接改指后不会沿用旧授权结论。静态检查到实际执行间的 TOCTOU 仍是边界，应在文档中保留，不声称完全消除。
7. 临时根按宿主的真实沙箱契约确定：WSL/Linux/macOS 可解析 `/tmp` 别名，Windows 使用原生临时路径，不把错误的跨平台字面根自动放行。
8. WSL 挂载转换只在有实际映射时启用。Linux/macOS 不把 `C:\...` 擅自改成 `/mnt/c/...`；POSIX 反斜杠名称不套用 Windows 分隔和转义规则。

### 测试与阶段出口

- 纯函数表驱动测试可在任意 OS 上验证 Windows/POSIX 语义；实际 realpath、软链、联接、大小写行为必须在对应文件系统跑。
- 使用运行时临时目录建立可销毁夹具；测试清理必须核实目标路径。不能写真实系统目录或把权限不足时的跳过算成功。
- 覆盖同盘/异盘、共享内/共享外、根目录、`..`、中文、空格、文件 URL、链接逃逸、不存在叶子、临时区、无权限与只读。
- 正向用例应避免误拒；反向用例须证明区外路径没有被当区内。临时目录例外不得使无权限或只读获得写能力。

主要影响：`functions.js`、`index.js`、路径与 gate 测试、路径文档。

## 阶段三：命令解释器与目录选择适配

### A. 命令解释器

- 先读取各平台实际工具 schema 和执行方式，区分 POSIX shell、PowerShell 与 cmd。工具名只是线索，不能仅凭 Windows OS 就把所有命令当 PowerShell。
- POSIX 保留现有路径回归；PowerShell 优先支持明确的文件 cmdlet、`-Path`/`-LiteralPath`、变量赋值、`$env:`、引号、反引号、管道及重定向。
- Windows PowerShell 与 PowerShell 7、别名和外部程序的参数语义须分别测试；无法识别的动态执行、脚本块、点调用、`Invoke-Expression` 等不得靠 POSIX 词法结果放行。
- 如目标 DSH 实际使用 cmd，应单独实现或明确标为未支持并失败关闭，不能写成“Windows 已支持”后遗漏它。
- “opaque”不能只作为提示：必须测试未知路径/动态路径不会因 paths 为空而绕过门控。必要时拒绝并建议改用显式文件工具；不得把一次授权扩大成整盘豁免。

### B. 目录选择与界面

- 先检测宿主 picker 能力：有原生选择器就调用；无能力时使用内置浏览器；用户取消不当成能力缺失，再弹第二个选择器。
- 根节点、盘符、主目录和挂载点来自宿主返回的数据或已核实的能力。WSL 的 `/mnt` 快捷入口只用于 WSL，不能作为 Windows 根。
- 目录路径以宿主返回值为准，浏览器不拼造跨平台根，也不扫描猜测 A–Z 盘符。
- 保留请求代次、读/写 family 隔离、关闭后失效、错误提示与键盘操作。无原生选择器不应让控件消失。

### 阶段出口

每个目标解释器都至少执行一组区内读写、区外读取审批、区外修改审批、拒绝/仅一次/总是和不确定命令测试。原生桌面与 Web UI 分别验目录选择与取消；测试矩阵中缺环境的格子保持“未验证”。

主要影响：命令分析、客户端目录浏览、相关宿主能力适配及测试；不修改宿主内部包。

## 阶段四：跨平台集成与发布

### 验证矩阵

| 环境 | 自动化最低要求 | 真机最低要求 |
|---|---|---|
| Linux 原生 CLI + Web | Ubuntu / Node 22，完整测试 | 授权与计数、无 native picker 回退、POSIX 命令 |
| WSL2 CLI + Web | Windows/POSIX 纯函数样例；WSL 实测另记 | Windows 挂载映射、WSL 根、临时区、计数 |
| Windows 原生 CLI + Web | Windows / Node 22，完整测试 | 实际默认解释器、盘符/UNC/联接、授权与计数 |
| Windows 桌面版 | 不能用 Windows CLI 结果代替 | 安装、客户端激活、WebView前后台/销毁、原生 picker、权限执行 |
| macOS 原生 CLI + Web | macOS / Node 22，完整测试 | 临时根/软链、卷大小写、picker、POSIX 命令与计数 |

CI 扩为 `ubuntu-latest`、`windows-latest`、`macos-latest`。纯 Node CI不代替 DSH 安装验证；至少对声明支持的两版 DSH 分别完成组合配置与启动，再逐项记录交互验证。若某版本的桌面构建不可取得，写清版本和缺口。

### 发布步骤

1. 运行语法检查、全部测试、文档链接检查及 `git diff --check`；记录各平台通过、失败、跳过原因。
2. 在独立目录使用 `npm pack`，校验 `package/` 顶层、manifest、locale、图标及全部运行依赖；继续采用精简运行包，仓库测试不必随包分发。
3. 用真实 `.tgz` 安装到干净 profile，检查配置合成、客户端接管和卸载。不直接手写当前 profile；涉及管理操作时通过受支持的插件管理入口并取得必要批准。
4. 分清仓库源码、实际安装副本、运行中的进程：宿主代码更新须按安装结果决定重载/重启；普通客户端变更也须验证送达，不凭 HMR 假设已生效。不得擅自重启用户正在使用的会话。
5. 更新兼容性说明、已知限制和 CHANGELOG；确认新版本号与发布说明后提交、推送、打标签。默认递增修复版本，不再静默覆盖已发布包或重写 `v1.3.0`。
6. 核对标签源码、安装包、SHA256 与 Release 附件一致；保留可回滚的前一版本，不再依赖多份无说明目录副本。

### 最终验收

用户不打开面板即可看到授权计数变化；同一操作在已声明支持的原生环境符合相同权限契约；不支持的解释器或路径形式明确拒绝而非静默越权。未通过的平台不列为“已兼容”。

## 四、实施记录（1.3.1，阶段一先行）

阶段零的两条事实改变了阶段一的选型：

- 列表读取会写会话日志。`dsh-commands` 的 `execute()` 每次调用都追加 `command/run` 与 `command/done`，
  所以“每 3 秒用 `/access-allow list` 校准”等于每分钟向会话写入约 40 条事件。周期同步因此被否决，
  即使它能满足“5 秒内可见”。
- 客户端可订阅的宿主事件是固定白名单（`dsh-api-remotes` 的 `API_REMOTE_FORWARDED_EVENTS`），
  插件不能注册自定义推送键，也没有通用的“授权已提交”事件。

阶段一改用的信号：授权页本身是会话状态里的 pending interaction。应答之后该标记消失，
`uiSession.sessionStatus` 也随之下发变化，这正是“弹窗已关闭、宿主已记录授权”的客户端可见边沿。
控制因此在两个边沿重读列表：`pendingInteraction` 消失，以及 `running` 由真转假（授权也可能在回合收尾时落下）。
读取有 250 毫秒节流，其余状态变化（例如未读标记）不触发读取；不新增任何定时器，空闲时为零请求，
因此不需要阶段一原本的“每分钟 20 次上限”。

这与阶段一的两个验收目标一致：可见延迟约为一次状态通知（通常远小于 5 秒），并且不产生日志写入。
被否决的候选（观察问答 waterfall、周期命令读取）在诊断文档 3.3 节仍有记录，不再采用。

尚未进入阶段二至四：路径语义、解释器分流、目录选择与三平台 CI 维持原文计划，未在本轮修改。
