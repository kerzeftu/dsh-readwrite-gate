# 授权说明

## 何时需要授权

在“工作区内读写”档位下，读取工作区和临时目录以外的路径，需要用户授权。两种工作区档位下的区外修改也会触发提示，但实际写入仍受 DSH 沙箱限制。

已有授权覆盖的路径不再重复询问。读取与修改分别检查：例如，将区外文件复制到工作区时，需要检查源文件的读取权限和目标文件的修改权限。

“无权限”禁止的访问以及“只读”禁止的修改不会通过授权提示解除。手动添加的读白名单是例外，见本文末尾说明。

## 如何选择

| 选项 | 效果 |
|---|---|
| 不允许 | 拒绝本次调用，不新增授权；再次越界时仍会询问。 |
| 仅一次 | 允许本次请求，不保留授权；后续同类请求仍会询问。 |
| 该对话中总是可以访问／修改 | 记录本次请求对应的目录；后续同类访问不再重复询问，可在面板中撤销。 |

读取请求显示“该对话中总是可以访问”，修改请求显示“该对话中总是可以修改”。允许读取不会自动允许修改；可写路径也会显示在面板的读栏中。

## “总是允许”覆盖哪些文件

**持续授权通常以目录为单位，不只针对提示中涉及的单个文件。** 如果请求的目标是目录，记录该目录；如果是文件，记录文件所在的目录。

例如，读取 `/etc/hostname` 时选择“该对话中总是可以访问”，记录的是 `/etc/`，授权范围包括该目录下的其他内容。确认前应核对提示中的授权目录；若只需本次访问，请选择“仅一次”。

面板中的目录以尾斜杠标识。移除该行会撤销对应目录的授权。

## 授权有效期

授权保存在 Harness 进程内存中。会话销毁或 Harness 重启后，授权失效；同一会话内重建 agent 不会清空授权。保存会话记录不等于保存授权。

派发的子会话可以继承父会话的实时授权，子会话的授权不会反向授予父会话。存储结构与继承规则见[架构说明](architecture.md)，设计原因见 [ADR 0003](decisions/0003-conversation-scoped-grants.md)。

授权通过 DSH 问题服务向用户请求，不是模型可自行调用的授权工具。提问服务不可用或请求被取消时，本次调用会被拒绝。

## 撤销授权

在“额外可读写文件”面板中，点击路径旁的 ✕ 即可撤销：

- 读栏：同时撤销该路径的读取和修改授权。
- 写栏：仅撤销修改授权。

也可以使用以下命令：

```text
/access-allow remove <path>
/access-allow remove-read <path>
/access-allow remove-write <path>
/access-allow clear
```

前三条分别撤销全部、读栏对应、写栏对应的授权；最后一条清空本对话的额外路径。撤销后，如果访问仍然超出当前档位的范围，且没有其他授权覆盖该路径，下次访问会重新询问。

## 为什么允许修改后仍然失败

插件授权和平台沙箱是两项独立检查。在两种工作区档位下，插件允许区外修改后，写入仍须通过 DSH 的 `workspace-write` 沙箱检查。因此，授权提示中的“允许”不保证实际写入成功，也不会改变沙箱范围。

## 手动添加的读白名单

`/access-allow add <path>` 添加的是读白名单。它与授权提示的持续授权不同：即使选择“无权限”，白名单中的路径仍允许读取。使用“无权限”前，如需完全禁止读取，应先检查并清除读白名单。

读白名单不授予修改权限。`/access-allow add-write <path>` 添加的修改授权仍受当前档位和平台沙箱限制。
