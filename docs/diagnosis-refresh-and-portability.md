# 计数刷新与跨平台兼容性诊断

日期：2026-11-15  
审查基线：`d29edd9`（1.3.0）  
状态：方案阶段，未实施修复。对应的[构建计划](build-refresh-and-portability.md)按阶段规定实现与验收。

## 1. 目标与边界

本轮处理两件事：授权后“额外可读写文件”的计数不能自行更新；插件需要面向 WSL2、原生 Windows、macOS、原生 Linux 使用者，而不是依赖作者的 WSL2 配置。

平台兼容须分开看宿主操作系统、命令解释器和界面载体。例如，Windows 终端可能运行 PowerShell，也可能连接到 WSL；Windows 桌面版中的文件操作则由桌面版宿主执行。浏览器所在的系统不决定文件路径语义。

本文件只诊断上述范围，不重新审查全部代码，不改变五档权限、目录授权粒度、读写分离或授权的内存生命周期，也不把静态命令分析宣称为操作系统级安全隔离。

## 2. 结论摘要

| 问题 | 结论 | 证据状态 |
|---|---|---|
| 批准目录后数字不变，打开面板才更新 | 控件所订阅的问答投影不覆盖本插件的直接服务问答；打开面板的显式读取才取得新值 | 已核实当前源码链路，与用户现象一致 |
| 监听窗口焦点能否保证刷新 | 不能。页面内部模态框关闭不等于窗口重新获得焦点 | 纠正此前方案 |
| 请求票号能否防止同时发出多个读取 | 不能。票号只抑制旧响应，必须另设请求中的状态 | 已核实实现职责 |
| 改浏览器代码是否足以保证所有平台兼容 | 不能。可减少操作系统耦合，但仍须验证 WebView 生命周期、宿主协议及实际安装副本 | 待分平台验收 |
| Windows 大小写是否完全没有处理 | 不是。`containsPath` 已对 Windows 路径转小写比较；仍须验证大小写敏感目录及其他路径形式 | 已核实，纠正此前表述 |
| 现有测试是否已经跨平台 | 仓库可移动不等于跨平台；CI 目前只有 Ubuntu，部分夹具仍使用 POSIX 路径 | 已核实 |

## 3. 计数刷新诊断

### 3.1 当前的数据链路

1. 宿主在 `runDialog` 中直接 `await ctx.userQuestions.ask(...)`。
2. 选择“总是”后，宿主调用 `grantPaths`，写入本对话的授权内存表。
3. 客户端通过已有的 `/access-allow list` 读取列表，列表同时用于面板和计数。
4. `AllowControl` 的刷新 effect 依赖权限档位及 `userQuestions.settled.length`；打开面板、手动增删路径时另有显式读取。

证据入口：[客户端刷新 effect](../client.js#L498-L551)、[宿主问答与授权写入](../index.js#L1016-L1055)。行号以本文件基线为准，维护时以函数名定位。

### 3.2 为什么投影没有提供这个通知

核查的 DSH `0.2.1-alpha.1` 安装源码中，`dsh-user-questions/lib/index.js` 的 `applyUserQuestionEvent` 从 `tool/call`、`tool/result` 和 PTC 相关事件折叠问答状态；直接服务方法 `ask` 则走 `user-questions/request` waterfall。司门直接调用该服务，不通过 `ask_user_question` 工具调用。

因此，不能把“用户在界面答完了问题”等同于“会话的 `userQuestions` 投影增加一项 settled”。该依赖不是本插件授权变化的可靠通知源。这不是目录授权没有保存：稍后打开面板便能读取新列表，说明至少用户反馈的这次操作已经写入宿主。

本轮实时 Inspect 的客户端 Event 目录没有提供通用的“授权变更”通知；这只说明已公开的目录没有该通知，不证明所有版本都不存在其他能力。`0.2.2-rc.3` 的对应实现还须在构建阶段单独核对，不能用 alpha.1 的源码替代该版本验证。

### 3.3 即使找到问答完成事件，也仍须处理时序

问答结束与授权内存表更新不是同一件事：`grantPaths` 位于 `await ask` 之后。若只在客户端的应答提交时读取，可能读到宿主尚未更新的状态。

可靠的推送应在宿主完成授权变更后发出，并携带会话标识。固定延迟一次读取只能降低竞态概率，不是提交完成的证明。

### 3.4 需要一起处理的生命周期问题

现有 `refreshTicket` 只解决较早请求覆盖较新请求，不限制并发数，也不代表组件仍挂载。刷新 effect 的清理目前还会让旧请求完成后执行 `setEntries(null)`；它不应清除新会话或新挂载实例的数据。

新增自动刷新前，必须统一处理：请求合并、会话切换、卸载、失败重试、后台暂停、断线恢复。否则计数问题可能变成过多请求或旧结果串到另一会话。

### 3.5 不采用的方案

- **不接管问答 waterfall**：它负责应答，不是被动广播；观察者不能依赖处理器加载顺序，更不能影响批准、拒绝、取消及错误传播。
- **不伪造会话事件**：不能为了刷新数字伪造工具调用或向会话日志追加未声明事件。
- **不只靠焦点或固定延迟**：内部弹窗关闭未必触发 `window.focus`；延迟读取仍有时序假设。
- **不把高频状态当通知**：不在每个流式 token 或统计更新时请求授权列表。

## 4. 跨平台诊断

### 4.1 已存在的适配与仍需解决的部分

| 范围 | 当前事实 | 构建时要验证或修正的内容 |
|---|---|---|
| 路径比较 | `containsPath` 区分 POSIX/Windows 分隔符，并对 Windows 转小写 | UNC 的共享根不能被 `..` 越过；盘符相对路径 `C:foo`、根相对路径 `\foo`、设备路径须明确处理；不能在大小写敏感目录中错误扩大授权 |
| 文件 URL | `fileUrlPath` 手工去 scheme，`normalizeUserPath` 另有一套处理 | `file:///C:/...`、`file://server/share/...`、localhost、百分号转义需统一；两入口必须得到同一宿主路径 |
| 实际路径 | `canonicalPathOf` 用 `realpathSync`，失败后按最后一个 `/` 找父目录 | 原生反斜杠路径的父目录回退不完整；联接、软链、失效路径、网络错误须区分；长期缓存可能在链接改指后过期 |
| 临时目录 | 同时纳入 `/tmp` 和 `os.tmpdir()`，并尝试 realpath | 原生 Windows 不能因 POSIX `/tmp` 字面量而默认放行错误位置；按宿主沙箱契约确认真正允许的临时根，不扩展“无权限/只读”写权限 |
| WSL 映射 | `windowsMounts` 读取 `/proc/mounts` | 仅在确认为 WSL 且存在真实挂载映射时启用；非 WSL 的失败不得影响插件加载 |
| 手动路径 | 支持引号、HOME、相对路径与 WSL 盘符映射 | POSIX 的反斜杠文件名不能被当 Windows 或 shell 转义误改；Windows 不应无条件采用 POSIX 解码规则 |
| 命令分析 | 现有分析器主要按 POSIX shell 语法工作 | 按实际工具与解释器选择分析器；不能把 PowerShell/cmd 命令直接按 POSIX 解析后宣布安全 |
| 目录浏览器 | `loadPlaces` 固定读取 `/mnt`，只认单字母目录快捷入口 | 原生 Windows 的盘符、UNC 根及 macOS/Linux 根应来自宿主目录能力；不能用 `/mnt` 作为所有平台的文件系统模型 |
| 测试 | gate 根目录已按仓库路径生成，仍有 `/opt`、`/etc` 等夹具；CI 仅 Ubuntu/Node 22 | 分离纯词法样例与本机文件夹具；在 Windows/macOS/Linux 上跑同一套回归，不静默跳过关键权限用例 |

证据入口：[宿主路径与临时区](../index.js#L38-L149)、[文件 URL](../functions.js#L259-L267)、[包含判断](../functions.js#L1209-L1246)、[手动路径](../functions.js#L1338-L1420)、[目录快捷入口](../client.js#L691-L710)、[测试夹具](../test/check-gate.mjs#L17-L25)、[现有 CI](../.github/workflows/ci.yml)。

以上是适配工作项，不代表每一种输入均已证明能够绕过权限。网络盘、macOS 卷的大小写规则、Windows 大小写敏感目录和桌面 WebView 行为均需要目标环境证据。

### 4.2 终端与桌面版的区别

- CLI 启动 Web UI：宿主在 CLI 所在系统执行文件操作，浏览器只显示控件。
- Windows 桌面版：需要单独验证插件加载、远程接口、目录选择器与 WebView 的可见性/销毁行为。浏览器测试不能替代桌面测试。
- 纯终端交互：若没有挂载 Web UI，客户端计数控件不适用；仍须测试权限门控、授权答复及无答复通道时的失败关闭。此文不承诺新增 TUI 控件。
- 远程宿主：浏览器的 `navigator.platform` 不能用于决定宿主路径格式。

## 5. 修复方向与承诺范围

计数修复优先寻找**授权提交后的、按会话区分的只读通知**。确认没有可用契约时，先采用共享、限频、仅可见页面运行的列表同步作为保底，焦点与前台恢复只是补充信号。详细的选型门槛和时效指标见[构建阶段一](build-refresh-and-portability.md#阶段一修复列表同步)。

跨平台修复遵循同一原则：路径由宿主解释、界面按能力工作、无法确定的访问不直接放行；不为提升兼容率取消权限限制。

本轮不能给出“所有平台保证兼容”的结论。最终应分别公布单元测试、原生 CI、DSH 组合加载、真实授权交互及桌面验收的结果。未运行的环境标为“未验证”，不能把 WSL2 结果写成 Windows 原生结果。
